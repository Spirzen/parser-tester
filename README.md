# Парсинг-тренажёр

Учебный сайт-мишень для уроков по веб-парсингу. Выглядит как живой каталог
вымышленного магазина «Тихая бухта», а на деле это набор статичных файлов:
нулевая нагрузка на сервер, предсказуемая структура, никаких реальных данных и
никакого юридического риска — ссылку можно давать всей группе.

Здесь есть то, чего обычно не хватает на «боевых» сайтах: все уровни заголовков,
вложенные `div`, списки и таблицы, соседние элементы, `data-*` атрибуты,
относительные пути, пагинация трёх видов, формы с hidden и csrf, куки,
редиректы, намеренно битая разметка, страницы с динамической подгрузкой,
JSON API, `robots.txt`, `sitemap.xml`, RSS и готовые сценарии для Scrapy.

## Быстрый старт

```bash
npm run build                   # node tools/generate.mjs --write && node tools/build.mjs
                                # site/ -> dist/: навигация, задания, sitemap, feed
node tools/serve.mjs --port 8000
# в другом окне
pip install -r examples/requirements.txt
python examples/smoke_test.py   # структура страниц и примеры согласованы
node tools/check.mjs            # 70 страниц, ссылки, контракты, 187 заданий
```

Сервер поднимает не только статику: на нём живут настоящие HTTP-ситуации,
недоступные на GitHub Pages — `301/302` и цепочка редиректов, коды `401/403/404/429/503`
с `Retry-After`, выдача `Set-Cookie` (включая `HttpOnly`), медленный ответ для
отработки `timeout`, страница в `windows-1251` и JSON API с параметрами `?page=&size=&category=`.
Полный список эндпоинтов сервер печатает при запуске.

## Модули

| Вкладка | Что тренирует |
| --- | --- |
| `basics/` | запрос и ответ, `requests` против `urllib`, кодировки, вежливость парсера |
| `selectors/` | CSS ↔ XPath ↔ BeautifulSoup, вложенность, соседи, атрибуты, `data-*`, шум и двойники |
| `http/` | заголовки, коды ответов, куки, редиректы, JSON API, RSS и sitemap как источник ссылок |
| `markup/` | заголовки, списки, таблицы, навигация по дереву и битая разметка на трёх парсерах |
| `pagination/` | нумерованные страницы, `rel="next"`, «показать ещё», бесконечная прокрутка, URL-паттерны |
| `forms/` | GET и POST, скрытые и csrf-поля, `select multiple`, эхо-эндпоинт |
| `js/` | ожидания Selenium и Playwright, SPA на хэш-роутинге, shadow DOM, iframe, ленивая загрузка |
| `scrapy/` | каталог и карточки, цитаты с авторами, правила краулера, выгрузка без дублей |
| `exam/` | 12 заданий на одном плотном полигоне + автопроверка без открытых ответов |

### Блок-тренажёр на каждой странице

В правом нижнем углу — панель «Тренажёр селекторов» (`assets/js/trainer.js`):
режимы CSS / XPath / регулярки, число совпадений, подсветка найденных узлов на
странице, вывод текста/атрибута/`outerHTML` и эквивалент на Python
(`soup.select(...)`, `tree.xpath(...)`, `re.findall(...)`). Клик по CSS- или
XPath-решению в блоке заданий отправляет его в панель. Горячая клавиша —
`Ctrl+Shift+S`. Кнопка в шапке страницы (и адрес с `?mode=exam`) включает режим
без подсказок: разборы в заданиях и сама панель скрываются — так страницу можно
давать группе как самостоятельную работу.

## Примеры кода

`examples/` — рабочие сценарии, они же проверяются в CI:

- `trainer.py` — адрес полигона (`PARSER_BASE_URL`), вежливый запрос с задержкой;
- `01_requests_basics.py` — статусы, заголовки, кодировка, сессия и куки, повтор на 429, переход на JSON API;
- `02_urllib_stdlib.py` — то же стандартной библиотекой: `Request`, отключение редиректов, `POST`, `gzip`;
- `03_bs4_tree.py` — `find`/`select`, `parent`/`siblings`, `data-*`, таблицы, сравнение трёх парсеров на битой разметке;
- `04_selenium_dynamic.py` — `WebDriverWait`, staleness, iframe, `shadowRoot`, куки браузера;
- `05_playwright_dynamic.py` — автоожидания, `expect`, перехват JSON-ответов, хэш-роутинг, `frame_locator`, бесконечная прокрутка;
- `06_scrapy_spider.py` — два паука: `catalog` (список → карточка) и `quotes` (пагинация по `rel="next"`);
- `smoke_test.py` — проверка согласованности страниц и примеров.

```bash
python examples/06_scrapy_spider.py catalog -O items.jsonl   # цитаты: ... quotes -O quotes.jsonl
```

## Публикация

Работают два сценария. Оба собирают `dist/` — в репозиторий артефакт не попадает.

**GitHub Pages** (`.github/workflows/deploy.yml`): в настройках репозитория
`Settings → Pages → Build and deployment → Source: GitHub Actions`. После этого
push в `main` собирает сайт и публикует `dist/`. Адрес — 
`https://<user>.github.io/parser-tester/`, поэтому все пути в разметке
относительные, а `sitemap.xml`, `feed.xml` и `robots.txt` на сборке получают
абсолютный адрес из переменной `SITE_BASE_URL`.

**Netlify / Cloudflare Pages** — если на уроках нужны настоящие HTTP-редиректы и
свои заголовки ответов: `netlify.toml` и `site/_redirects` уже настроены,
publish-каталог `dist`, команда сборки `npm run build`.

## CI (`.github/workflows/ci.yml`)

push/PR и еженедельно по расписанию:

1. `quality` — генератор сверяется с исходниками, сборка, `tools/check.mjs`
   (структура страниц, битые ссылки и якоря, валидность JSON, контракт заданий,
   относительность путей, чек-лист учебных конструкций, текст без смешения алфавитов);
2. `smoke` — `python tools/validate_tasks.py --zero` (каждый селектор из заданий что-то находит) и `python examples/smoke_test.py` против локального сервера;
3. `urllib`, `scrapy`, `playwright` — прогон соответствующих примеров;
4. `selenium` — только по кнопке `workflow_dispatch` (зависит от Chrome/драйвера в раннере).

Так полигон не может «тихо» разъехаться с тем, что студенты пишут на уроке.

## Как устроено и как расширять

```
site/                 исходники: страницы, ассеты, данные
  data/tasks/*.json   задания модулей (сборка склеивает в dist/data/tasks.json)
  <module>/*.html     страница модуля — всегда один уровень вложенности
tools/generate.mjs    массовые страницы: пагинация отзывов, каталог и карточки Scrapy, длинный список
tools/build.mjs       site/ -> dist/: навигация, блок заданий, футер, sitemap.xml, feed.xml, robots.txt
tools/check.mjs       проверки качества
tools/validate_tasks.py прогоняет css/xpath из карточек заданий по сборке
tools/serve.mjs       локальный сервер с «живыми» HTTP-ответами
```

Новая страница добавляется по контракту `docs/AUTHORING.md`: маркеры
`<!-- inject:nav -->`, `<!-- inject:tasks -->`, `<!-- inject:footer -->`,
атрибут `data-page`, относительные пути, задания в `site/data/tasks/<module>.json`.
Массовые страницы правятся в `tools/generate.mjs`, а не руками: после правки
данных выполните `node tools/generate.mjs --write` и `node tools/check.mjs`.

## Правила полигона

Все имена, города, цены, почты и телефоны вымышлены, домены — `example.com`.
Парсить можно всё, включая `robots.txt`; раздел `/private/` запрещён намеренно —
это упражнение на `ROBOTSTXT_OBEY`. Даже здесь отрабатываем вежливость:
свой `User-Agent` с контактом, `Crawl-delay`, пауза между запросами,
повтор только после ошибки.
