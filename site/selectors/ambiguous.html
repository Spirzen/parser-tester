Шум: одинаковые классы в разных секциях

Живая вёрстка так и выглядит: .card встречается в новостях, в заказах, в каталоге и в блоке поддержки. Побеждает тот, кто умеет ограничивать область поиска, а не тот, кто придумал более длинный селектор.

На этой странице .card, .item, .row и .title намеренно переиспользованы в пяти секциях. Перед каждым заданием решите: «в какой секции я ищу?» — и начинайте селектор с ограничителя section[data-zone="…"].

Один id и много классов с одним именем

У этого заголовка есть id="title", а у десятка элементов ниже — class="title". Селектор #title найдёт один узел, .title — все карточки, а h2#title вернёт именно заголовок.

Похожие id

Три разных атрибута id, которые легко перепутать при копировании селектора из DevTools.

Дефис: #product-card-1

Подчёркивание: #product_card_1

Верхний регистр: #ProductCard1

В CSS имена id чувствительны к регистру символов, а в HTML-разметке id обязан быть уникальным: три похожих — легальные три разных узла. Одинаковые классы — обычное дело; одинаковые id — ошибка вёрстки.

Как с этим работать

  1. Начинайте селектор с контейнера секции, а не с имени класса: [data-zone="orders"] .item.
  2. Различайте роли через атрибуты: [data-field="sku"] надёжнее, чем .row .item:first-child.
  3. Считайте скрытое отдельно: .hidden-block, [hidden], style="display:none", .is-hidden-row, .visually-hidden.
  4. Проверяйте уникальность текста ссылки: шесть «Подробнее» — это шесть разных адресов, и ни одна из них не «главная».
