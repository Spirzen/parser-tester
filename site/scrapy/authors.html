Авторы ленты — урок про Item Relation

У каждого автора есть профиль прямо здесь, а его цитаты — на страницах ленты (1, 2) с якорями вида quotes.html#q01. Паук собирает два разных «представления» одного сущности и склеивает в один Item.

Идея приёма. На странице цитат мы знаем автора лишь частично (имя + ссылка на профиль). Переходя по ссылке, паук получает биографию и счётчики. Правильная схема: в parse_quote отдать response.follow(author_url, callback=self.parse_author, meta={"quote_item": item}), а в parse_author дописать поля в переданный Item и вернуть его один раз на каждую цитату.

Как это выглядит в пауке

class QuotesAuthorSpider(scrapy.Spider):
    name = "quotes-authors"
    start_urls = ["https://…/scrapy/quotes.html"]

    def parse_quote(self, response):
        for q in response.css("blockquote.quote"):
            item = {
                "text": q.css("small.quote::text").get(),
                "author": q.css("span.author::text").get(),
                "tags": q.css("div.tags a.tag::text").getall(),
                "url": response.url,
            }
            # одна цитата — один Item; профиль автора добираем отдельно
            yield item

    def parse_author(self, response):
        row = response.css("tr.author-card")
        yield {
            "name": row.css("a.author-link::text").get(),
            "alias": row.css("span.alias::text").get(),
            "born": row.css("time.dob::attr(datetime)").get(),
            "birthplace": row.css("td.birthplace::text").get(),
            "bio": row.css("td.bio::text").get(),
            "quotes": int(row.css("td.quote-count::attr(data-count)").get()),
        }

follow против urljoin. Ссылки «все цитаты» ведут на другие страницы с якорем (quotes.html#q01). Помните: якорь серверу не передаётся — response.follow(...) придёт на всю страницу, а «нужную» цитату вы уже отличите по id блока в HTML. Ручной urljoin(response.url, href) даёт тот же адрес, но не подхватывает callback и не уважает dont_filter — на этом полигоне достаточно response.follow.
