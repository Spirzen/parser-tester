Зеркало выгрузки: с чем сравнивать своего паука

Три эталонных JSON-файла и образец правильной построчной выгрузки. Собираете каталог — прогоните паука и сверьте с эталоном: поля, типы, порядок, дубли. Расхождение — это баг парсера, а не «мелочь».

../data/products.json

12 карточек каталога: sku, цены, остатки, теги, характеристики. Эталон для пар к index.html + item-01.html.

../data/quotes.json

../data/reviews.json

Образец JSONL: как выглядит правильная выгрузка

Каждая строка файла items.jsonl — самостоятельный JSON-объект. Ни запятых между строками, ни внешнего массива: так делает FEEDS = {"items.jsonl": {"format": "jsonlines"}}. Если ваш файл «не читается построчно» — вы выгрузили json.dump(list), а не фид.

Чек-лист сверки (5 строк → 5 проверок)

  1. Число записей: wc -l items.jsonl против meta.count в эталоне (для товаров — 12).
  2. Типы: "price": 2490, а не "2 490 ₽"; строку из HTML приводите в pipeline (int(re.sub(r"\D", "", text))).
  3. Полнота: ни одного пустого поля там, где эталон даёт значение (oldPrice может быть null — сверяйтесь с карточкой).
  4. Дубли: sort items.jsonl | uniq -d пусто. Не пусто — включите дедупликацию по sku.
  5. Кодировка: кириллица читаема, а не \u0422...: FEED_EXPORT_ENCODING = "utf-8".

Быстрый способ сверить без глаз: python -m json.tool ../data/products.json и построчный json.loads вашего файла, затем сравнение множеств {(p["sku"], p["price"])}. Разница множеств и есть ваш баг-репорт.
