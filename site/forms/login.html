Форма входа: POST, токен и куки

Вход — это всегда два запроса: сначала GET страницы с формой, чтобы забрать токен и куку, затем POST с логином, паролем и теми же скрытыми полями. Здесь можно разобрать оба шага, потому что отправлять форму некуда: на GitHub Pages сервера нет.

Куда смотрит action="#". Полигон живёт на GitHub Pages как чистая статика, поэтому адрес формы намеренно пустой — POST-запроса не будет. На локальном сервере (node tools/serve.mjs) есть учебный эндпоинт /http/echo: он возвращает JSON с присланными полями, заголовками и куками. Подставьте action="/http/echo" руками — и увидите тело собственного запроса.

Атрибут required работает только в браузере: requests его не видит и отправит пустоту, если вы не проверили сами.

Парольное поле читается из разметки так же, как любое другое, — значение в name держится в type="password".

Отключённое поле: пользователь не меняет, браузер не отправляет, в request_body его не будет.

Поле readonly, в отличие от disabled, уходит в запрос с тем значением, что лежит в value.

Значение приходит письмом и в HTML его нет: такие поля парсят не из формы, а из почты или SMS-шлюза — на полигоне их нет вовсе.

Откуда брать токен

Токен лежит в разметке до отправки, а его копия — ещё и в атрибуте формы. Тренируем внимательность: значение в data-csrf-token у form обязано совпадать с value скрытого поля.

import requests

session = requests.Session()                      # куки живут в сессии, а не в одном запросе
session.headers.update({'User-Agent': 'trainer/1.0 (+учебный проект)'})

page = session.get('http://localhost:8000/forms/login.html', timeout=15)
form = BeautifulSoup(page.text, 'html.parser').find('form', id='login-form')
token = form.find('input', {'name': 'csrf_token'})['value']          # то же, что form['data-csrf-token']

resp = session.post('http://localhost:8000/http/echo', data={
    'csrf_token': token,
    'redirect': form.find('input', {'name': 'redirect'})['value'],
    'login': 'ivan.petrov',
    'password': 'учебный-пароль',
    'remember': 'yes',
    'partner': form.find('input', {'name': 'partner'})['value'],
}, timeout=15)
print(resp.status_code, resp.json()['fields'])

Про Session и Cookie

  • Куку выдаёт сервер в ответе заголовком Set-Cookie; браузер сохраняет её и подставляет в каждый следующий запрос того же домена.
  • Токен — часть тела запроса, а не заголовка транспорта: он лежит в HTML формы и при POST уезжает в request_body. Сервер сверяет токен из куки и токен из формы.
  • Один requests.get сессии не заменяет: без requests.Session() кука session_id до следующего запроса не доживёт, и авторизованный ответ вы получите 401.
  • HttpOnly куку не прочитать из JavaScript и не вытащить из HTML — её видно только в заголовках ответа (resp.cookies).
  • Признак успешного входа — не текст «Добро пожаловать», а редирект (302 + Location), новая кука в Set-Cookie или изменение набора прав в API-ответе.
session.cookies.set('theme', 'dark', domain='localhost')     # подставляем свою куку
resp = session.get('http://localhost:8000/http/cookies', timeout=15)   # эндпоинт отдаёт три Set-Cookie
print(resp.cookies)                                          # session_id, cart, theme
print(session.get('http://localhost:8000/forms/results.html', timeout=15).cookies)

На реальном сайте проверьте себя так: откройте DevTools → Network, вызвите Copy as cURL, сравните заголовок Cookie, тело --data-raw и то, что собрал ваш session.post. Совпадение до байта — признак того, что вы ничего не забыли.
