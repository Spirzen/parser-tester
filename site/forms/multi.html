Анкета товара: форма, в которой есть всё

Здесь собрано то, что на реальных сайтах обычно попадается по отдельности: textarea, select multiple, файлы, одинаковые name у двух полей, fieldset с legend, кнопки с разным formaction и два одинаковых id. Задача разбора — не «найти все input», а предсказать тело запроса.

Форма никуда не отправляется. Атрибут action здесь — #, потому что на GitHub Pages сервера нет. Кнопка «Сохранить черновик» показывает второй способ: у неё собственный formaction, и по ней браузер уйдёт на results.html. На локальном сервере вместо # подставьте /http/echo — и сравните fields в ответе с таблицей внизу.

Основное

pattern — тоже только браузерная проверка: парсер о ней не знает.

У textarea нет атрибута value: содержимое лежит между тегами, поэтому читают .get_text(), а не ['value'].

Цена и склад

Атрибута value нет: браузер отправит old_price= — пустую пару, а не отсутствие ключа.

multiple: выбранных опций несколько, и в запросе name повторится столько же раз.

Значения всегда в атрибуте value, причём date — строго в формате ГГГГ-ММ-ДД.

Внимание: у этого поля двойник по id — он называется так же, как поле «Название для склада» выше. См. сноску под формой.

Метки и состояние

Метки: name="tags[]" — квадратные скобки в имени реальны на старых PHP-сайтах, для парсера это просто символы в значении атрибута.

name="condition"
name="delivery" — ни одна кнопка не отмечена

Неотмеченная группа не отправляется целиком: ключа delivery в теле не будет.

Файлы и спецификация

Два разных поля с одним name и одним id: в теле будет две пары подряд, и обычный словарь data= такое не выразит — нужен список кортежей.

datalist — подсказки ввода, а не поля формы: значений оттуда в запрос не попадает ничего.

Три кнопки отправки отличаются: у первых двух есть name и value, значит нажатая кнопка добавит в тело свою пару (publish=yes или save=draft). У reset имени нет — он исчезает бесследно.

Про двойники id. В анкете два раза встречается id="name" (поле «Название для склада» и «Менеджер партии») и два раза id="spec" (оба select). HTML так делать не разрешает, но парсеры ведут себя по-разному: soup.find(id="name") и driver.find_element(By.ID, "name") вернут первый элемент, а soup.select("#name") и find_elements — оба. Отсюда практическое правило: для форм надёжнее искать по name и контексту (fieldset, label), а не по id.

Что уедет в тело запроса

Правило одно: пара name=value появляется, если у элемента есть name, он не отключён и его тип участвует в отправке. Всё остальное — детали типов.

Разбор этой формы кодом

from bs4 import BeautifulSoup
import requests

BASE = 'http://localhost:8000'
html_text = requests.get(f'{BASE}/forms/multi.html', timeout=15).text
soup = BeautifulSoup(html_text, 'html.parser')
form = soup.find('form', id='product-form')

# 1. Имена полей без привязки к типу — и сколько раз имя повторяется
names = [el['name'] for el in form.find_all(attrs={'name': True})]
doubles = {n for n in names if names.count(n) > 1}          # {'spec'}

# 2. Скрытые поля, которые легко потерять
hidden = {el['name']: el.get('value', '') for el in form.find_all('input', {'type': 'hidden'})}

# 3. Отмеченные чекбоксы и радиокнопки: remember = checked
marked = form.find_all('input', {'type': ['checkbox', 'radio']})
chosen = [(el['name'], el.get('value', 'on')) for el in marked if el.has_attr('checked')]

# 4. Все выбранные опции, включая multiple
def selected_options(field):
    return [o.get('value') or o.get_text(strip=True) for o in field.find_all('option')
            if o.has_attr('selected')]

payload = [
    ('name', form.find('input', {'name': 'name'})['value']),
    ('category', selected_options(form.find('select', {'name': 'category'}))[0]),
    ('description', form.find('textarea', {'name': 'description'}).get_text()),
    ('warehouse', 'wh-bay'), ('warehouse', 'wh-sorted'),        # список кортежей, не словарь
    ('spec', 'водонепроницаемость'), ('spec', '10 АТМ'),
    ('condition', 'new'),
    ('tags[]', 'фонари'), ('tags[]', 'лагерь'), ('tags[]', 'уценка'), ('tags[]', 'on'),
    ('publish', 'yes'),
]
r = requests.post(f'{BASE}/http/echo', data=payload, timeout=15)
print(r.json()['fields'])           # сравните с таблицей: delivery и moderator_note там не будет

С файлами data= уже не обойтись: requests сам переключится на multipart/form-data, как только вы передадите files=.

with open('fonar.jpg', 'rb') as fh:
    r = requests.post(f'{BASE}/http/echo',
                      data=[('name', 'Фонарь «Тихая бухта» 400'), ('warehouse', 'wh-bay')],
                      files={'photo': ('fonar.jpg', fh, 'image/jpeg'),
                             'gallery[]': [('a.jpg', open('a.jpg', 'rb'), 'image/jpeg'),
                                           ('b.pdf', open('b.pdf', 'rb'), 'application/pdf')]},
                      timeout=15)
print(r.json()['content_type'])     # multipart/form-data; boundary=...

Порядок полей важнее, чем кажется. Браузер идёт по дереву документа, а не по алфавиту: name идёт раньше title, а spec из третьего fieldset — раньше units. На сайтах с подписью тела запроса (некоторые платёжные формы) порядок даёт другую подпись, и запрос отвергается без внятной ошибки.
