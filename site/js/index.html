Страницы с JavaScript: почему обычный запрос видит пустоту

Разбираемся, чем «исходный HTML» отличается от «DOM после скриптов», и учимся выбирать между ожиданием, прямым запросом и браузером.

Главная причина пустоты. requests.get() и urllib получают файл с сервера и останавливаются. BeautifulSoup парсит ровно этот файл. JavaScript в этом процессе не выполняется ни секунды: если строки таблицы дорисовывает lazy-table.js, в ответе requests их не будет — будет пустой <tbody>.

Два «снимка» одной страницы

Исходный HTML (виден curl / requests)DOM после JS (виден в DevTools)
Кто формируетсервер (у нас — GitHub Pages как файл)браузер: setTimeout, fetch, createElement

Selenium или Playwright: чем ждать

Selenium

  • driver.implicitly_wait(3) — неявное: перед каждым поиском узла ждёт до N секунд; просто, но глобально и вслепую.
  • WebDriverWait(driver, 5).until(EC.visibility_of_element_located(...)) — явное: ждёт конкретное условие.
  • Переключение контекста: switch_to.frame(), execute_script() для теней.

Playwright

  • Автоожидания по умолчанию: page.locator('tr.row-stock').wait_for(), действия сами ждут готовности элемента.
  • page.wait_for_url, wait_for_load_state('networkidle'), expect(...).to_be_visible().
  • frame_locator() для iframe, pierce/evaluate для shadow DOM.

Ждать сеть или DOM?

  • Ждать DOM-признак (строка появилась, #status сменил текст) — надёжно: вам нужен результат работы скрипта, а не факт окончания загрузок.
  • Ждать сеть (networkidle, page.wait_for_response()) — удобно, когда данных в DOM ещё нет, а JSON уже прилетел: можно перехватить ответ целиком.
  • Пустое ожидание по времени (time.sleep(3)) — плохая привычка: на медленной машине урок «падает», на быстрой вы ждёте лишнее.
  • Комбинация на этом полигоне: таблица появляется через фиксированные 1,5 с, поэтому visibility_of_all по tr.row-stock — самое честное ожидание.

Как искать настоящий JSON-эндпоинт

  1. Откройте DevTools (F12) → вкладка Network → фильтр Fetch/XHR.
  2. Перезагрузите страницу (Ctrl+R) и покликайте навигацию: каждый клик, который что-то догружает, — это запрос.
  3. Смотрите на Path: на spa.html это ../data/site-stats.json — один файл вместо трёх кликов.
  4. Вкладка Response покажет тот JSON, что вернётся вашему requests.get(). Если ответ — HTML-заглушка, эндпоинт придуман вами неверно.
  5. Правой кнопкой по запросу → Copy → Copy as cURL: превращает запрос в команду; Copy as fetch — в JS-код. Вставьте cURL в любой онлайн-конвертер или в subprocess, но для урока достаточно requests.get(url, headers={...}).

Правило выбора: сначала ищем JSON (быстро, стабильно, без браузера); браузер подключаем, когда данных в сети нет — их действительно вычисляет JS (анимация, тень, вычисления на клиенте).
