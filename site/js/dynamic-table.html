Ожидания: явные и неявные

from selenium import webdriver
from selenium.webdriver.common.by import By
from selenium.webdriver.support.ui import WebDriverWait
from selenium.webdriver.support import expected_conditions as EC

driver = webdriver.Chrome()
driver.get(url)                                  # страница получена, JS ещё не отработал

# неявное: «подожди до 5 с, пока узел вообще появится в DOM» — действует на любой поиск
driver.implicitly_wait(5)

# явное: ждём конкретное условие — все 6 строк стали видимыми
rows = WebDriverWait(driver, 5).until(
    EC.visibility_of_all_elements_located((By.CSS_SELECTOR, "tr.row-stock"))
)
data = {r.get_attribute("data-sku"): int(r.get_attribute("data-qty")) for r in rows}
# Playwright: автоожидание «из коробки»
page.goto(url)
page.wait_for_selector("tr.row-stock")          # то же самое, короче
pairs = page.eval_on_selector_all(
    "tr.row-stock",
    "rs => rs.map(r => [r.dataset.sku, +r.dataset.qty])",
)

Ловушка обновления. Кнопка «Обновить данные» запускает обновление таблицы и меняет data-qty. Если прочитать таблицу до клика и после — цифры разойдутся, и это не баг парсера, а гонка. Привяжите чтение к смене индикатора: после клика дождитесь, пока #status содержит «данные обновлены», а первичную отрисовку — «данные готовы» (EC.text_to_be_present_in_element / wait_for_function).

Разница presence_of и visibility_of: первый ждёт появления узла в DOM, второй — ещё и видимости (не display:none, ненулевые размеры). Скрытый блок .hidden-block из других модулей через visibility_of не дождаться — только через presence_of.
