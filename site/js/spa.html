SPA ещё не инициализирован

Если вы видите этот текст и после загрузки — включите JavaScript или откройте сайт через локальный сервер: эндпоинт отдаёт только node tools/serve.mjs.

Куда пропадает хэш

Хэш не уходит на сервер. Адрес …/js/spa.html#/reviews — это тот же самый файл spa.html: всё, что после #, браузер не включает в HTTP-запрос. Поэтому requests.get("…/spa.html#/reviews") вернёт байт-в-байт тот же HTML, что и без хэша, — ни таблиц, ни списков раздела там нет. Маршрут «живёт» только в браузере.

Проверьте прямо сейчас: откройте эту страницу с хэшем #/reviews и нажмите F5 (прямой заход). Контент раздела «Отзывы» появится — скрипт читает location.hash при старте. А curl "spa.html#/reviews" и curl "spa.html" дадут один и тот же ответ: для HTTP-клиента различия не существует.

Что искать во вкладке Network

  1. Фильтр Fetch/XHR → при загрузке виден один запрос: data/site-stats.json.
  2. Переключение маршрутов новых запросов не создаёт — SPA читает кэш: данные уже получены.
  3. Правой кнопкой по запросу → Copy → Copy as cURL — это и есть весь «API» страницы.
import requests

# вместо трёх кликов браузером — один запрос к найденному эндпоинту
stats = requests.get(BASE + "/data/site-stats.json", timeout=10).json()
for row in stats["sections"]["prices"]["rows"]:
    print(row["sku"], row["price"])

Вывод: для SPA сначала кликаем руками и смотрим сеть, потом парсим JSON напрямую. Браузер (Selenium/Playwright) остаётся для случаев, когда эндпоинта нет — данные вычисляются на клиенте или закрыты токеном, который умеет выдавать только страница.
