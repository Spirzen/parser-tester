Культура парсинга

Технически возможно собрать почти всё. Законно и этично — заметно меньше. На этом полигоне можно ничего не бояться, но привычку вежливости вырабатывать лучше сразу.

robots.txt: первый файл проекта

Файл лежит по адресу ../robots.txt и описывает, что разрешено автоматическим клиентам. Он не защищает данные — это договорённость, которую исполняют честные боты. Читают его до первого запроса к контенту.

Фрагмент файла целиком

Разбор директив
ДирективаЗначение на полигонеЧто делает парсер
User-agent: *блок для всех, кого нет в спискеищем свой блок по имени, иначе читаем звёздочный
Allow: /разрешено всё сверху внизработает как исключение: конкретнее — значит приоритетнее
Disallow: /private/раздел с «личными» страницамине заходим и не передаём эти URL краулеру
Disallow: /*?debug=запрет по маске, * — любые символыподдержка масок есть не во всех парсерах robots.txt
Crawl-delay: 1одна секунда между запросамиtime.sleep(1) в цикле или DOWNLOAD_DELAY = 1 в Scrapy
Sitemap:ссылка на карту страницотдаём sitemap.xml как источник URL вместо обхода вручную
Rss:ссылка на лентулента — бесплатный источник дат и ссылок

В Python есть готовый читатель: from urllib.robotparser import RobotFileParser, далее rp.read() и rp.can_fetch(url, ua). Он не понимает нестандартных строк вроде Rss: — их добираем сами.

User-Agent: представьтесь

Пустой или чужой User-Agent — самая частая причина молчаливого 403. В учебных скриптах пишите честно: имя проекта и контакт, куда админ пришлёт письмо.

Задержки и повторные запросы

Сервер — не ваш: он считает соединения, платит за трафик и держит очередь. Три практик, которые закрывают 90 % проблем.

  1. Пауза между запросами. От Crawl-delay из robots.txt, а если его нет — от 0,5 до 2 секунд. time.sleep(1) в конце цикла, а не в начале: так не спим после последней страницы.
  2. Разумный таймаут. get(url, timeout=(3.05, 27)) — 3 секунды на соединение, 27 на чтение. Запрос без timeout может висеть минутами и блокировать урок.
  3. Повтор с нарастанием. При 429 и 503 читаем Retry-After и ждём столько, сколько просят; нет заголовка — удваиваем паузу: 1, 2, 4 секунды, максимум три попытки.
import time
import requests

UA = {"User-Agent": "TikhayaParser/1.0 (+contact@example.com)"}
DELAY = 1.0  # Crawl-delay из ../robots.txt

def fetch(url, attempts=3):
    for attempt in range(attempts):
        r = requests.get(url, headers=UA, timeout=(3.05, 27))
        if r.status_code == 200:
            return r
        if r.status_code in (429, 503):
            wait = float(r.headers.get("Retry-After", 2 ** attempt))
            time.sleep(wait)
            continue
        r.raise_for_status()
    raise RuntimeError(f"сервер не отдал {url} за {attempts} попыток")

for page in range(1, 7):
    html = fetch(f"http://localhost:8000/pagination/page-{page}.html")
    time.sleep(DELAY)

Одна секунда × 600 страниц = десять минут урока. Это нормально. Десять параллельных запросов без задержки — уже атака, даже на учебный полигон: CONCURRENT_REQUESTS в Scrapy держим маленьким.

Юридическая рамка

Можно

  • Читать открытые страницы этого полигона: все данные вымышлены.
  • Сохранять себе публичные технические метаданные: цену, наличие, дату обновления.
  • Использовать официальный API, если он есть, — это быстрее и честнее.

Нельзя без разрешения

  • Личные данные, переписка, закрытые разделы, обход авторизации и капчи.
  • Нарушать условия использования реального сайта: ToS важнее технической возможности.
  • Перепубликовать чужой контент целиком — товарные описания и тексты охраняются.

На реальных проектах последовательность действий всегда одна: читаем robots.txt и условия использования → ищем API или выгрузку → только потом HTML. Директивы, адреса и e-mail в этом уроке придуманы; на чужом сайте читайте его собственные правила.
