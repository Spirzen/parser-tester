JSON-API полигона: сначала данные, потом разметка

Почти всё, что видно на витрине, лежит в файлах products.json, articles.json, reviews.json, quotes.json и site-stats.json. Прямой запрос к JSON быстрее и устойчивее, чем разбор HTML, — и почти всегда законнее.

Статические файлы: работают где угодно

Это обычные файлы репозитория: их отдаёт и node tools/serve.mjs, и GitHub Pages, и диск. Открывать с диска можно, но браузер не покажет их как «ответ API» без запуска сервера.

Все пять файлов — обычная статика: их отдаёт как есть и GitHub Pages, и node tools/serve.mjs, и даже диск через file://. Никакой серверной логики в них нет: это готовые выгрузки, а не живой API. У всех файлов есть служебный блок meta — не забывайте его при разборе: data["products"], а не весь корень.

Локальные эндпоинты: нужен serve.mjs

Эти адреса существуют только когда запущен node tools/serve.mjs: они умеют пагинацию, фильтр по категории, коды ошибок и заголовки кэша. Без сервера вы получите 404 — файлов с такими именами в dist/ нет.

import requests

session = requests.Session()
session.headers.update({"User-Agent": "TikhayaParser/1.0 (+contact@example.com)"})

page = session.get("http://localhost:8000/http/api/products",
                   params={"page": 1, "size": 8}, timeout=10)
page.raise_for_status()
data = page.json()
print(data["total"], data["pages"], data["next"])

items = data["items"]
while data["next"]:
    page = session.get("http://localhost:8000" + data["next"], timeout=10)
    data = page.json()
    items += data["items"]

# Тот же файл напрямую, без эндпоинта:
local = session.get("http://localhost:8000/data/products.json", timeout=10).json()
print(len(local["products"]), local["meta"]["currency"])
# Тот же запрос на чистом urllib: байты, ручная склейка параметров, сам decode.
import json
import urllib.request
import urllib.parse

base = "http://localhost:8000/http/api/products"
query = urllib.parse.urlencode({"page": 1, "size": 8, "category": "свет"})
req = urllib.request.Request(f"{base}?{query}", headers={"User-Agent": "TikhayaParser/1.0"})

with urllib.request.urlopen(req, timeout=10) as resp:
    data = json.loads(resp.read().decode("utf-8"))   # .json() в requests делает это сам

print(data["total"], data["pages"], data["next"])
products = json.loads(
    urllib.request.urlopen("http://localhost:8000/data/products.json", timeout=10).read()
)

Поле против поля: что теряется при парсинге HTML

Одни и те же данные в JSON и на витрине selectors/products.html
ПолеВ JSONВ HTMLЧто теряется
артикулskuarticle[data-sku]ничего: значение в атрибуте
ценаprice = 2490.price[data-price]в тексте — «2 490 ₽» с пробелом: число берите из атрибута
старая ценаoldPrice = null.price--old[data-old-price]JSON различает null и отсутствие ключа, HTML — только «элемента нет»
вложенные характеристикиspecs { вес, нагрузка }список dl.spec на карточке товарапары «ключ-значение» надо собирать циклом и чистить пробелы
признак наличияinStock, stock[data-stock] и текст «нет в наличии»0 и отсутствующий атрибут — разные случаи, на витрине оба выглядят пусто
рейтингrating = 4.6[data-rating]в тексте рядом «из 5» — не тащите его в число
дата обновленияupdatedAt = …T10:15:00Ztime[datetime] и видимый текствидимая дата без времени и без часового пояса
продавецseller.sellerв выдаче API продавца нет — он только в разметке

Ссылки на карточки в JSON (url: "item-03.html") относительные и без папки: к ним придётся добавлять scrapy/ вручную. В HTML та же ссылка уже содержит путь — проверяйте urljoin, иначе соберёте несуществующие адреса.

Порядок действий на реальном проекте: открыть DevTools → Network → найти JSON-ответ → читать его. HTML разбираем только тогда, когда данных в ответе нет вовсе.
