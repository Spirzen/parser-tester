Как выглядит обмен байтами

Всё, что происходит «в сети», — два текстовых сообщения. Слева то, что отправляет ваша программа, справа то, что возвращает сервер.

GET /http/news.html?page=2 HTTP/1.1
Host: localhost:8000
User-Agent: TikhayaParser/1.0 (+contact@example.com)
Accept: text/html
Accept-Encoding: gzip, deflate
Connection: keep-alive

HTTP/1.1 200 OK
Content-Type: text/html; charset=utf-8
Content-Length: 8412
Set-Cookie: session_id=demo-session-42; Path=/; Max-Age=3600
X-Powered-By: parsing-trainer

<!DOCTYPE html>
<html lang="ru"> ...

Пустая строка между заголовками и телом — часть протокола. В requests её видно не всегда, в curl -v — всегда.

Коды состояния и действия парсера

Что означает ответ и что с ним делать
КодНазваниеЧто это значитДействие парсера
200OKдокумент на местеразбираем тело
301Moved Permanentlyадрес переехал навсегда, новый — в Locationидём за редиректом и обновляем список URL
302Foundвременный редиректидём за Location, в кэш не пишем
304Not Modifiedсервер подтвердил: тело не менялосьберём локальную копию, отправляем If-None-Match
400Bad Requestошибка в нашем запросе: кривые параметрыправим URL, повторять бесполезно
401Unauthorizedнужна аутентификация, есть WWW-Authenticateлогин или ключ в заголовках
403Forbiddenсервер понял, кто вы, и не хочетпрекращаем: повторные попытки только ухудшают
404Not Foundстраницы нет (или адрес собран неверно)проверяем маску URL и границу пагинации
429Too Many Requestsпревысили лимит, ждём Retry-Afterспим столько, сколько просят, и снижаем темп
500Internal Server Errorупал сервер, это не наша винаповторяем 1–2 раза с паузой и фиксим лог
503Service Unavailableперегрузка или техработы, часто есть Retry-Afterэкспоненциальная задержка, максимум несколько попыток

requests не считает ошибкой ничего, кроме исключения сети: get() вернёт объект и для 404, и для 500. Проверка обязательна: r.raise_for_status() или явное сравнение r.status_code.

Где смотреть заголовки

  1. DevTools браузера. F12 → Network → Reload → клик по документу → вкладки Headers: Request headers и Response headers. Ищите фильтр Fetch/XHR, чтобы найти JSON-эндпоинт страницы.
  2. curl с флагом -i. Покажет ответ вместе с заголовками: curl -i http://localhost:8000/http/echo.
  3. curl с -v. Добавляет заголовки запроса и детали TLS: удобно, когда сервер «не понимает», кто к нему пришёл.
  4. Сам объект ответа. r.request.headers — что ушло, r.headers — что вернулось, r.history — по каким редиректам прошлись.
curl -i  "http://localhost:8000/http/status?code=429"   # увидим Retry-After: 2
curl -i -L "http://localhost:8000/http/redirect-301"    # -L = следовать редиректу
curl -s  "http://localhost:8000/http/echo"              # что сервер видит в нашем запросе
curl -i  "http://localhost:8000/http/protected"         # 401 без ключа
import requests

r = requests.get(
    "http://localhost:8000/http/protected",
    headers={"X-API-Key": "trainer-demo-key"},
    timeout=10,
)
print(r.status_code)          # 200
print(r.request.headers)      # что реально ушло, включая наш ключ
print(r.history)              # [] — редиректов не было

r429 = requests.get("http://localhost:8000/http/status?code=429", timeout=10)
print(r429.headers["Retry-After"])   # 2 — спим ровно столько, сколько просят

Эндпоинты: только локальный сервер

GitHub Pages отдаёт одни файлы, поэтому «живое» поведение протокола имитирует node tools/serve.mjs. Запуск: node tools/build.mjs, затем node tools/serve.mjs, адрес по умолчанию — http://localhost:8000. Без сервера эти адреса вернут 404: в dist/ таких файлов нет.

Учебные эндпоинты полигона
МетодАдресЧто демонстрирует

GET/http/status?code=429любой код: 200 401 403 404 429 503, у 429 и 503 есть Retry-After
GET/http/redirect-301настоящий 301 на /http/final.html; рядом /http/redirect-302 и цепочка /http/redirect-chain

GET/http/slowотвечает с задержкой ?ms=3000 — тренировка timeout
GET/http/charsetHTML в windows-1251: урок про кодировки в basics/encoding
GET/http/protected401 без заголовка X-API-Key: trainer-demo-key

Статические «файлы API» (../data/products.json и другие) работают где угодно — и на Pages, и с диска. Их список и примеры запросов: http/api.html.
