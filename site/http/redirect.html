Редиректы: страница, которой больше нет

Через четыре секунды браузер сам уйдёт на final.html — это meta refresh, самый «человеческий» способ переезда. Здесь он работает учебным примером: сравните его с настоящими 301 и 302.

Если вы читаете страницу глазами — она убежит. Чтобы остаться и всё разобрать, откройте её через curl или сохраните: curl -s http://localhost:8000/http/redirect.html -o redirect.html. В отличие от HTTP-редиректа, curl сюда не пойдёт: переезд выполняет браузер, а не сервер.

Правило парсера. HTTP-редирект ловится на уровне библиотеки и почти не мешает. meta refresh и location — это уже контент: первый ещё можно прочитать из head, второй исполняет только браузер.

Отсюда практический вывод: meta refresh «читается» только теми, кто смотрит в разметку, — браузерами и BeautifulSoup. Чистые HTTP-клиенты его пропускают.

Почему на GitHub Pages нет настоящего 301

Хостинг статичных файлов не умеет отвечать 301: GitHub Pages отдаёт только то, что лежит в репозитории, и живёт в подпапке /parser-tester/. Поэтому настоящие редиректы полигона живут в трёх местах: файл _redirects для Netlify, конфигурация netlify.toml в корне проекта и маршруты node tools/serve.mjs для локальной проверки. На Pages вместо 301 работает эта страница: meta refresh — единственная «переадресация», которую можно положить в HTML.

Кнопка: подменить адрес без перехода

Иллюзия для наблюдательных: адрес в строке изменится, документ останется этим. Так делают SPA-страницы, и так парсер «теряется», если доверяет адресу.

Адрес в строке: —

Как это видит Python

import requests
from urllib.request import urlopen, Request

URL = "http://localhost:8000/http/redirect-301"

r = requests.get(URL, timeout=10)                 # по умолчанию allow_redirects=True
print(r.status_code, r.url)                       # 200 .../http/final.html
print([h.status_code for h in r.history])         # [301]

r = requests.get(URL, allow_redirects=False, timeout=10)
print(r.status_code, r.headers["Location"])       # 301 /http/final.html

# urllib следует за редиректом всегда и сам; возвращает финальный URL:
with urlopen(Request(URL), timeout=10) as resp:
    print(resp.status, resp.geturl())             # 200 .../http/final.html

# Цепочку из трёх редиректов видно целиком:
r = requests.get("http://localhost:8000/http/redirect-chain", timeout=10)
print(len(r.history))                             # 3

Если нужно собрать адреса-источники (например, старые URL для карты редиректов), ставьте allow_redirects=False и берите Location. Если нужна финальная страница — оставляйте как есть и смотрите в r.url, а не в переменную url.

Локальные адреса для проверки

Работают только когда запущен node tools/serve.mjs: на статичном хостинге таких файлов нет.

  • /http/redirect-301 — честный 301 на final.html
  • /http/redirect-302 — временный 302 на ту же цель
  • /http/redirect-chain?hop=1 — цепочка из трёх редиректов
  • /http/status?code=… — произвольный код состояния

Чтобы сравнить три механизма одним взглядом: curl -i http://localhost:8000/http/redirect-301 покажет заголовок Location, а curl -i http://localhost:8000/http/redirect.html — обычный ответ 200 с тегом meta внутри.

Куда именно ведёт эта страница — final.html: три факта и кука-маркер, которая появляется только после визита.
