HTML-разметка и навигация по дереву

Парсер не «ищет текст»: он ходит по дереву узлов. Здесь — карта дерева, все способы перехода между узлами в BeautifulSoup и разбор отличий bs4-дерева от DOM браузера.

Заголовки

h1–h6, уровни вразнобой, data-level, мусор в футере секции.

Списки

Вложенность до четырёх уровней, dl/dt/dd, смешанные списки, пустой ul, скрытые li.

Таблицы

thead/tbody/tfoot, colspan и rowspan, вложенная таблица, разъехавшиеся строки, CSV рядом.

Битая разметка

Незакрытые теги, CDATA, сущности и три парсера на одном фрагменте.

1. Дерево вместо текста

BeautifulSoup разбирает строку HTML в дерево узлов: теги становятся объектами Tag, текст между ними — узлами NavigableString, комментарии — Comment. Узел хранит родителей и детей, поэтому переход «вверх-вниз-вбок» — это обращение к атрибутам, а не повторный поиск по строке.

Исходная разметка

<article class="post">
  <header>
    <h2>Заголовок</h2>
    <p class="meta">Автор: <a>Тихая бухта</a></p>
  </header>
  <section>
    <ul class="tag-list"><li>поход</li><li>кемпинг</li></ul>
  </section>
</article>

То же как дерево

article.post                # Tag
├─ header                   # Tag, parent == article
│  ├─ h2                    # Tag, next_sibling == p.meta
│  │   └─ "Заголовок"        # NavigableString
│  └─ p.meta
│     ├─ "Автор: "           # текст тоже узел
│     └─ a → "Тихая бухта"
└─ section
   └─ ul.tag-list
      ├─ li → "поход"        # previous_sibling == None
      └─ li → "кемпинг"      # previous_sibling == li "поход"

Между тегами почти всегда лежит «мусорный» текст: переводы строк и отступы. article.children вернёт их вместе с элементами, поэтому для обхода лучше find_all(recursive=True) или фильтр по Tag.

Живой фрагмент для отработки

Тот же пример в настоящем HTML: выделяйте узлы в тренажёре селекторов справа и сверяйте с кодом ниже.

Штормовая куртка «Маяк»

Продавец: Мастерская Прибой

  • мембрана
  • капюшон

8 990 ₽

Фрагмент учебный: id и классы здесь настоящие, данные вымышленные.
soup = BeautifulSoup(html, "html.parser")

card.header.h3.get_text()                  # 'Штормовая куртка «Маяк»'

card.select_one(".price").get("data-price")        # '8990' — значение атрибута
[tag.get_text() for tag in card.select("li.tag")]  # ['мембрана', 'капюшон']

2. Переходы между узлами

Атрибуты и методы навигации BeautifulSoup

tag.parentsитератор всех предков вверх до htmlфильтр «элемент лежит внутри статьи»: any(p.name == "article" for p in li.parents); доступен parents[i] и find_parent("div").

3. find и find_all: чем фильтровать

Сигнатура поиска
АргументСмыслПример
имя тега (первый позиционный)строка, список, регулярное выражение, функция или Truesoup.find_all(["h2", "h3"]), soup.find_all(re.compile("^h[1-6]$"))
attrs (словарь и **kwargs)соответствие атрибутов; для class — через class_=soup.find_all("td", attrs={"data-price": True}), soup.find("a", class_="btn")
string=текст узла: строка, список, регулярка, функция; вместо устаревшего text=soup.find_all(string=re.compile("₽"))
limit=остановиться после N совпаденийsoup.find_all("li", limit=3)
recursive=Falseискать только среди детей текущего узлаul.find_all("li", recursive=False) — пункты без вложенных списков
find_* против select*атрибуты против CSS/XPathsoup.select("ul.tree > li"), soup.select_one("[data-sku]"), в lxml-режиме soup.select("//ul/li")
 
# только верхний уровень вложенности — ровно 4 пункта, а не 15
soup.find("ul", class_="tree").find_all("li", recursive=False)

# атрибут без значения: важно, что он есть
soup.find_all("tr", attrs={"data-status": "shipped"})

# функция-фильтр: строки, где больше трёх ячеек
soup.find_all("tr", lambda tr: len(tr.find_all(["td", "th"])) > 3)

# limit= дешевле, чем срез: не обходит весь документ
first_two = soup.find_all("a", href=True, limit=2)

find возвращает None, find_all — пустой список. Из-за этого soup.find("table")["id"] падает с TypeError, а [t["id"] for t in soup.find_all("table")] просто даёт пустой ответ. Проверяйте, что вернулось, и не подменяйте find_all одиночным find «на всякий случай».

4. Чем bs4-дерево отличается от DOM браузера

Один и тот же файл глазами парсера и глазами браузера
СитуацияBeautifulSoup (исходный HTML)DOM браузера / Selenium, Playwright
Открыли тег и не закрылиПарсер достраивает дерево по своим правилам: узел может «уехать» внутрь соседа. Итог зависит от html.parser / lxml / html5lib.Браузер чинит разметку по стандарту HTML5 и всегда показывает исправленное дерево.
Содержимое дорисовал JavaScriptНе видно вообще: bs4 не исполняет скрипты.Видно — но только после wait_for / sleep, иначе парсер увидит половину страницы.
display: none, hiddenУзел обычный, текст достаётся через get_text().Element есть в DOM, но не виден: find_element пройдёт, visibility_of — нет.
Комментарии и CDATAУзел Comment, виден через string= только с явным фильтром.Comment-ноды существуют, но textContent их не отдаёт.
Регистр тегов<B> и <b> — разные имена для html.parser, один и тот же тег для lxml.Регистр не важен, теги всегда в нижнем регистре.
Пробелы между тегамиПолноценные NavigableString: next_sibling попадает в перевод строки.Текстовые узлы тоже есть, но nextElementSibling их пропускает — сразу следующий элемент.
Вложенные «незаконные» теги<p><div> остаётся как есть или разрывается — зависит от парсера.Браузер гарантированно закроет <p> перед <div>.
Скорость и доступностьЧитает строку: requests.get(...).text за десятки миллисекунд, работает без браузера.Нужен браузер, ожидание загрузки, иногда обход капчи.

Отсюда главное правило модуля: сверяйте исходный HTML и DOM. Получите файл через curl или requests.get(...).text, разбейте его BeautifulSoup и сравните количество узлов с document.querySelectorAll('...').length в консоли браузера. Разница и есть ваш баг: либо JavaScript, либо битая разметка, либо другой парсер.

import re, requests
from bs4 import BeautifulSoup

html = requests.get(url, timeout=15).text
soup = BeautifulSoup(html, "html.parser")          # стабильный результат на ломаной разметке
count_html = len(soup.select("li.product-item"))   # что видит парсер
# count_dom  = document.querySelectorAll("li.product-item").length   → в консоли браузера
print(count_html, count_dom, re.findall(r"<li\b", html))
