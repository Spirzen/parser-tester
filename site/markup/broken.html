Битая разметка: один файл, три дерева

Реальный HTML редко бывает валидным: незакрытые абзацы, лишние закрывающие теги, атрибуты без кавычек, CDATA и текст вне тегов. Парсеры чинят это по-разному — и на одном и том же файле вы получаете разное количество узлов.

Как устроен этот урок

Вся битая разметка на странице собрана в одном месте — между комментариями broken:start и broken:end. Это правило сборки тренажёра: чек-лист ищет именно эти маркеры, а всё остальное на странице обязано быть валидным.

  1. Читайте разделы «Одна строка — три парсера» и «Что делает каждый парсер».
  2. Скачайте страницу: requests.get(url).text или curl -s … > broken.html.
  3. Разбейте один и тот же файл тремя парсерами и сравните счётчики.
  4. Откройте страницу в браузере и посмотрите, куда переехал блок «Задания»: незакрытая таблица в конце раздела утягивает за собой разметку, а браузер переносит её «наружу».

Эффект на этой странице ожидаемый: незакрытые <p>, <div> и <table> в живом образце меняют порядок блоков в браузере. Ровно это и есть предмет урока.

Одна строка — три парсера

Таблица построена на реальных замерах: каждая строка — фрагмент из живого образца ниже, разобранная html.parser и lxml из BeautifulSoup 4.15. Колонка «браузер / html5lib» описывает правило стандарта HTML5, по которому работает html5lib.

Что делает каждый парсер

html.parser
Входит в стандартную библиотеку Python, зависимостей не требует. Разбирает «как написано»: незакрытые теги остаются открытыми и съедают соседей, лишний закрывающий тег игнорируется, обёртку <html><body> не добавляет. Быстрый и предсказуемый на плохой разметке — его результаты легче объяснять на уроке, но дерево может быть «кривым».
lxml
Библиотека на C (pip install lxml), самая быстрая. Агрессивно лечит разметку: закрывает p, li, td, добавляет html и body, умеет soup.select("//xpath") и полноценный :not(). Часть мусора (CDATA) выбрасывает молча — данные теряются без ошибки.
html5lib
pip install html5lib. Парсит по стандарту HTML5, то есть строит то же дерево, что браузер. Медленнее всех и ставится отдельно, зато спорные случаи (незакрытая таблица, вложение блочных тегов) решаются так, как их увидит пользователь. Используйте как «эталон», когда расходятся первые два.

Правило выбора: начинайте с html.parser (не нужен компилятор, результат одинаков на всех машинах), переходите на lxml ради скорости и XPath, а html5lib держите для сверки «как в браузере». Один и тот же парсер должен быть указан во всех скриптах проекта: смена парсера меняет количество найденных узлов, а это выглядит как «сайт изменился».

def cells(tr, expected):
    """Возвращает ровно expected значений: недостающие — None, лишние — в '_extra'."""
    raw = [td.get_text(strip=True) for td in tr.find_all(["td", "th"], recursive=False)]
    rec = dict(zip(expected, raw[:expected]))
    for i in range(len(raw), expected):
        rec[expected[i]] = None
    if len(raw) > expected:
        rec["_extra"] = raw[expected:]
    return rec
