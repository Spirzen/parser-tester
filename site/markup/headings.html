Заголовки: уровни, порядок, мусор

На реальной странице заголовки не выстроены по лесенке: уровень четвёртый может идти раньше второго, «h3» оказывается подписью в футере, а data-level противоречит тегу. Здесь все эти случаи собраны вместе.

Контракт полигона: <h1> на странице ровно один — он вверху, всё остальное размечено как h2…h6. Задания модуля строятся на этом правиле.

Все уровни по порядку

Учебная лесенка: каждый следующий заголовок стоит «внутри» предыдущего по смыслу, но не в разметке — заголовки в HTML не вкладываются друг в друга, они идут соседями.

Уровни вразнобой

Порядок «2 → 3 → 4» нарушен намеренно: страница склеена из трёх чужих шаблонов. Считать вложенность по номеру уровня нельзя — только по фактическим родителям в дереве.

Сначала четвёртый

Блок «Доставка» переехал из подвала сайта в середину статьи: тег остался h4, хотя по структуре это обычный раздел второго уровня.

Шестой раньше пятого

Мелкий технический заголовок из старой вёрстки.

А это пятый

Он стоит ниже шестого: если вы искали «последний уровень перед списком», селектор по h5 рядом не пройдёт.

Третий без второго рядом

Заголовок секции «Отзывы» из блока комментариев. Формально это h3, но ближайший h2 выше — «Уровни вразнобой», и он к отзывам не относится.

Четвёртый внутри третьего

Сосед, а не потомок: в дереве они лежат в одном section.

Заголовки с атрибутами

Часть заголовков размечена id и data-level. Значения data-level в двух местах не совпадают с фактическим тегом: так выглядит разметка, которую сгенерировала одна CMS, а значения проставила руками другая.

Заметка о наличии

Тег h3, обещает уровень 4.

Подзаголовок к заметке

Тег h4, обещает уровень 3.

Размерная сетка

Здесь всё честно: h3 и data-level="3".

Уход за мембраной

Заголовок вложен в div.card: parents[0] — div, parents[1] — section, parents[2] — main.

Самый глубокий

Два одинаковых div.card подряд — типичный дублированный шаблон.

Служебный заголовок скрытого блока

Предыдущий h2 скрыт стилем: BeautifulSoup его найдёт, Selenium с visibility_of — нет. Это единственный h2 на странице с атрибутом data-level, и стоит он не в начале документа.

Мусор в футере секции

Внизу секции лежит подвал с подписками и вакансиями. Его заголовки — тоже h3 и h4, и обычный запрос «собери все h3» приносит четыре лишних пункта: три из footer и один из скрытого блока.

Как отбирать заголовки

Три приёма

По тегу

soup.find_all(["h2", "h3"])                     # два уровня одним запросом
soup.find_all(re.compile("^h[1-6]$"))           # любые заголовки по регулярке
soup.find_all("h3", limit=3)                    # первые три, без обхода всего файла

По атрибуту

soup.find_all(attrs={"data-level": "3"})        # обещает уровень 3, теги разные
soup.find_all("h3", attrs={"data-level": True}) # только размеченные data-level
soup.find(id="sizes")                           # один узел; id уникален, пока его не продублировали
[h.get("data-level") for h in soup.find_all("h2")]

Исключить мусор

def content_heading(h):
    return not any(getattr(p, "name", None) in ("footer", "aside") for p in h.parents)

real = [h for h in soup.find_all(["h2", "h3"]) if content_heading(h)]

# то же селектором: заголовки, не лежащие в подвале
soup.select("section > h2, section > p + h3")
# и «последний заголовок перед списком» — через соседей, а не по номеру уровня
h3.find_next("ul")

Сортировка «по уровню» (min(int(t.name[1]) for t in headings)) и проверка иерархии (h4 без h3 выше) — стандартная часть валидатора статей. На этой странице она упадёт намеренно: уровень четвёртый идёт раньше третьего, а скрытый h2 вообще не виден в браузере.
