Таблицы: от честной разметки до разъехавшихся строк

Таблица — самый обманчивый формат. Внешне все строки выглядят одинаково, а внутри rowspan съедает ячейку, colspan сдвигает колонки, вложенная таблица добавляет лишних tr, а строки расходятся с шапкой. Здесь пять таких случаев и CSV рядом.

1. Большая таблица остатков

Полный набор конструкций: caption, двухуровневая thead с colspan и rowspan, tbody со слиянием первой колонки и tfoot с итогами.

4. Данные в атрибутах, а не в тексте

Ячейки показывают человеку короткую подпись, а настоящее значение сидит в data-*. Такой приём любит клиентский JavaScript: текст перерисовывают, значения читают из атрибутов.

5. «Разъехавшаяся» таблица

В шапке пять колонок, а в строках — три, пять, шесть и семь ячеек: экспорт из учётной системы, где часть колонок склеилась, часть добавилась. Это учебный образец того, почему нельзя полагаться на индекс колонки.

head = [th.get_text(strip=True) for th in soup.select("#shifted-table thead th")]
n = len(head)                                        # 5

def to_record(tr, head):
    cells = [td.get_text(strip=True) for td in tr.find_all(["td", "th"], recursive=False)]
    rec = {}
    for i, value in enumerate(cells):
        key = head[i] if i < n else f"extra_{i - n + 1}"   # лишнее не теряем
        rec[key] = value
    if len(cells) < n:                                 # короткий ряд: сдвигаем с конца?
        rec["_short"] = True                           # нет: только помечаем и разбираем отдельно
    return rec

records = [to_record(tr, head) for tr in soup.select("#shifted-table tbody tr")]

Правило устойчивого парсинга: сопоставляем колонку по заголовку, а не по позиции, и держим «хвосты» в отдельном поле. Строки с colspan при этом всё равно врут — у строки от 27 февраля ячейка colspan="2" скрывает сразу две колонки, и по индексу туда попадёт «1 · 1 690». Для таких выгрузок надёжнее читать исходный CSV или JSON, а не HTML.
